# Deployment Plan: Groww Mutual Fund RAG Assistant

This document outlines the architecture, requirements, and step-by-step instructions for deploying the Groww Mutual Fund RAG Assistant using **Railway** (for the backend and persistent database) and **Vercel** (for the Vite + React frontend).

---

## 1. Architecture & Hosting Strategy

The application consists of three main components:
1. **Backend (Railway)**: FastAPI web server running the Python RAG engine, guardrails, and daily refresh scheduler.
2. **Database (Railway Volume)**: ChromaDB (embedded in the Python process, saving data to `data/vector_store/`).
3. **Frontend (Vercel)**: React/Vite web application located in the `/frontend` subfolder of the repository.

### 🔑 Critical Deployment Requirements
* **Persistent Disk / Volume Mount**: ChromaDB is an embedded database. The hosting provider for the backend must support persistent storage mapped to `/app/data/`, otherwise the indexed embeddings will be wiped every time the server restarts or redeploys.
* **Environment Variables**: 
  * The backend requires `GEMINI_API_KEY` to call Gemini models.
  * The frontend requires the `VITE_API_URL` environment variable at build-time to point to the backend service.

## 2. Step-by-Step Deployment Guide

### Part 1: Deploying the Backend on Railway

Railway is ideal for the backend because it supports Python out-of-the-box and allows mounting a persistent storage volume to save the ChromaDB database.

#### Step 1: Create a Railway Project and Deploy
1. Sign in to your [Railway Account](https://railway.app).
2. Click **+ New Project** > **Deploy from GitHub repo**.
3. Select your repository: `aishwary-bangre/Groww-Mutual-Fund-RAG-Assistant`.
4. Click **Deploy Now**.
5. Once initialized, go to your service card and click **Settings**.
6. Under **Public Networking**, click **Generate Domain** to create a public URL (e.g., `https://groww-mutual-fund-rag-assistant-production.up.railway.app`).

#### Step 2: Mount a Persistent Volume (For ChromaDB)
Since the backend uses a local ChromaDB database stored in the `data/` folder, you must add a persistent volume so that embeddings are saved permanently.
1. In your project canvas, click on the **Groww-Mutual-Fund-RAG-Assistant** service card.
2. Go to the **Settings** tab.
3. Scroll down to the **Volumes** section and click **+ Add Volume** (or **Mount Volume**).
4. Set the settings:
   * **Mount Path**: `/app/data`
5. Save the volume configuration.

#### Step 3: Configure Environment Variables
Go to the **Variables** tab of the service and add the following variables:
* `GEMINI_API_KEY`: `your_gemini_api_key_here`
* `REFRESH_TIME`: `00:00` (daily refresh time in HH:MM format based on server time)
* `HOST`: `0.0.0.0`
* `PORT`: `8000` *(Railway automatically exposes this port, or assigns its own `$PORT` variable)*
* `VECTOR_STORE_PATH`: `data/vector_store`

#### Step 4: Configure Start Command
If Railway doesn't auto-detect the start command, configure it in **Settings** > **Service** > **Deploy** > **Start Command**:
```bash
python backend/app.py
```

Railway will rebuild your service. You can monitor the deploy logs. Once running, visit `https://<your-railway-url>/health` to confirm the backend status.

---

### Part 2: Deploying the Frontend on Vercel

Vercel is optimized for frontend applications. Since your Vite React app is in the `/frontend` subfolder, we configure Vercel to build from there.

#### Step 1: Import the Project in Vercel
1. Log in to [Vercel](https://vercel.com).
2. Click **Add New** > **Project**.
3. Import your GitHub repository: `aishwary-bangre/Groww-Mutual-Fund-RAG-Assistant`.
4. In the Project Configuration card, adjust the following settings:
   * **Framework Preset**: Select **Vite** (if not auto-detected).
   * **Root Directory**: Click **Edit** and select the `frontend` directory. Click **Continue**.

#### Step 2: Configure Environment Variables & Build Settings
Under the **Environment Variables** section in Vercel, add:
* **Key**: `VITE_API_URL`
* **Value**: `https://<your-railway-url>` (the domain generated by Railway in Part 1, e.g. `https://groww-mutual-fund-rag-assistant-production.up.railway.app`)

#### Step 3: Build & Deploy
1. Click **Deploy**.
2. Vercel will install packages (`npm install`), build the production assets (`npm run build`), and host the site.
3. Once finished, Vercel will provide a public URL for your UI dashboard (e.g. `https://groww-mutual-fund-rag-assistant.vercel.app`).

### Part 3: Alternative Deployment (VPS with Docker)

For developers wanting to host the system on a single Ubuntu VPS (like AWS or DigitalOcean) with docker-compose:

#### Step 1: docker-compose.yml
Create `docker-compose.yml` in the root:
```yaml
version: '3.8'

services:
  backend:
    build:
      context: .
      dockerfile: Dockerfile
    ports:
      - "8000:8000"
    volumes:
      - rag_data:/app/data
    env_file:
      - .env
    restart: always

volumes:
  rag_data:
```

#### Step 2: Dockerfile
Create `Dockerfile` in the root:
```dockerfile
FROM python:3.10-slim

WORKDIR /app

RUN apt-get update && apt-get install -y --no-install-recommends \
    build-essential \
    && rm -rf /var/lib/apt/lists/*

COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

COPY . .

EXPOSE 8000

CMD ["python", "backend/app.py"]
```

## 3. Post-Deployment Verification

1. **API Health Sync**: Load the Vercel URL. Check the header to see if the connection indicator says **Connected** with a green signal.
2. **Endpoint check**: Query `https://<your-railway-url>/health`. The response should display database count and status:
   ```json
   {
     "status": "healthy",
     "llm_model": "gemini-2.5-flash",
     "database": {
       "status": "connected",
       "record_count": 79
     }
   }
   ```
3. **Session State**: Verify that refreshing the page retains chat history in the sidebar (uses browser `localStorage`).
